Where it fits

402Signal sits between discovery and execution.

  1. Need
  2. Candidates
  3. 402Signal check
  4. Route + evidence
  5. Agent pays seller

A live routing request costs $0.01 USDC. 402Signal does not hold keys or pay the selected API on your behalf. Your agent keeps the wallet.

What gets checked

Payment challenge
Whether the endpoint returned a payment challenge we can read.
Payment details
payTo, amount, asset, and rail as returned at request time.
Invocation
Whether a call contract is listed (method and input schema).
Freshness
When the check was made, if we have a timestamp.

When evidence exists, readiness is labeled DISCOVERED, PAYABLE, INVOCABLE, or RECENTLY VERIFIED. Missing evidence is UNKNOWN, not no.

How agents use it

  1. Ask what is listed for a need. Free catalog search (GET /preview) returns candidates. These are listings, not live checks.
  2. Your agent pays 402Signal $0.01 USDC and sends POST /route with that need. An unpaid call returns HTTP 402.
  3. 402Signal checks the endpoint at request time. If a usable payment path is verified, you get a route plus evidence. A paid route can also return compared candidates. If not, the response is a miss: no qualifying endpoint was verified.
  4. Your agent then pays the selected seller. 402Signal does not take custody and does not pay the seller for you.

The API may include a miss_reason. Optional prefer_network: base, solana, or algorand.

Catalog claims and 402Signal observations

Catalog fields are what a directory listed. 402Signal-observed fields are what we recorded from the endpoint at request time. They stay separate. UNKNOWN is better than a guess.

Quickstart

HTTP

Unpaid POST /route with {"need":"weather"} returns HTTP 402. Sign the matching $0.01 USDC option from accepts[], then retry the same POST with PAYMENT-SIGNATURE.

Unpaid POST /route 
curl -sS -D - https://402signal.com/route -H 'Content-Type: application/json' -d '{"need":"weather"}'
