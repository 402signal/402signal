An example

Your agent finds a weather API for 2 cents.

Before it pays, 402Signal checks whether the API responds with usable payment terms, whether the price is still within your 2-cent limit, and whether it meets your other routing rules.

With optional v4 protection enabled in your app, the seller's fresh offer must also match the recorded terms before your payment code is called. A changed price, different recipient or expired record stops the handoff.

If the API still costs 2 cents and qualifies, the routing check costs $0.003: $0.023 combined, before any network fees. Your agent then decides whether to pay the API directly. If nothing qualifies, there is no routing charge.

Optional v4 protection

Still the same deal at payment time?

An API can change its terms after it is discovered. V4 gives your app a signed record to compare with the seller's fresh payment request immediately before signing.

Enable require_route_binding: true and integrate the local route guard. It verifies the record, checks the exact URL, request method and body, and compares the full payment offer. Changed terms, failed verification or expired evidence block the handoff to your payment code.

Your wallet still validates and signs the actual transaction. This is an opt-in integration, not an automatic lock on every agent payment. Some APIs, including those with changing personalized offers or different request bodies, cannot use this check. Add v4 to your buyer.

Awaiting anchor

A record of what was checked.

A payment receipt shows that money moved. The routing record captures the request, the observed terms and the decision evidence. If someone edits your saved record later, verification against the public log fails.

402Signal records routing evidence in an append-only Merkle log. Think of it as publishing a fingerprint of the evidence, not the private details themselves. Cumulative checkpoints are anchored on Algorand MainNet with native Falcon-1024 authorization.

V4 requires a signed log receipt immediately. The on-chain anchor follows separately; a pending record is not yet confirmed on-chain. The record supports checking what 402Signal observed, not proving that a seller delivered accurate data.

To check a specific decision later, securely keep the verification record returned with the paid route. Private replay outcomes can retain the evidence; they are not a recovery service. Keep your own copy outside public logs.

Falcon-1024 authorizes the checkpoint transaction. It does not make seller payments or API responses post-quantum secure.
