How routing works

Discovery sources publish metadata about x402 services. That metadata can describe an endpoint that no longer returns a usable HTTP 402, that changed its payment terms, or that lacks enough information to construct a call. A paid POST /route check observes the endpoint's current HTTP 402 payment requirements and applies the caller's constraints to those observed options.

Stages of a paid check

DISCOVER
Search supported discovery sources for the requested capability and assemble a working set of candidate URLs.
PROBE
Request each selected candidate and parse the current HTTP 402 payment requirements. A payable hit is a complete observed option. An invocable hit is payable plus enough input-schema information to construct the call.
EVALUATE
Apply the caller's constraints to the payment options returned during this request. Discovery listings do not satisfy a network lock or a price bound.
SELECT
Return the selected route and selected_payment when an observed option qualifies. Otherwise return a typed miss that reports why evaluation stopped.

Execution boundary

402Signal
Discovers candidates, probes them, applies constraints, returns a route or typed miss, and commits routing evidence. It does not hold buyer keys, sign the selected service's payment, or execute that service.
Caller
Retains custody of keys, signing, the selected service's payment, and execution of the seller request.

The $0.01 USDC paid on POST /route is a routing fee for this check. It is separate from whatever the selected seller charges.
