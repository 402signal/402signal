Developer API

Use 402Signal over HTTP or MCP. POST /route with the capability you need. An unpaid call returns HTTP 402. Pay $0.01 USDC, retry the same request, and receive a route with selected_payment or a typed miss.

402Signal does not hold the buyer's keys or execute the selected service's payment.

POST /route → unpaid HTTP 402 → pay $0.01 USDC → retry → route or typed miss.

Send POST /route with the capability your agent needs. Use your own need string. Unpaid: HTTP 402. Sign a matching $0.01 USDC option and retry with PAYMENT-SIGNATURE (or X-PAYMENT).

Example request. Unpaid POST /route 
curl -sS -D - https://402signal.com/route -H 'Content-Type: application/json' -d '{"need":"YOUR_NEED"}'
Compact responses

Paid check: HTTP 200 with live, url, invocable, selected_payment, target.

Typed miss: HTTP 503 with miss_reason.

Agents that intend to pay should POST, not GET. GET with Accept: application/json (or no Accept) returns the 402 challenge. Browsers that send text/html get a human page.

MCP endpoint: https://402signal.com/mcp. Tools: route (paid live check), preview (catalog search, not probed), and validate (unpaid seller probe).

MCP server URL 
https://402signal.com/mcp

initialize, tools/list, preview, and validate need no payment. Unpaid route returns HTTP 402; retry the same tools/call with a matching $0.01 USDC signature.

Common recipes

networks is a hard rail lock. prefer_network is a weak ranking preference. cheapest is cheapest among currently probed eligible candidates. fastest is this-request probe RTT, not settlement latency. payable can be true while invocable is false. constraints_unmet means every probed candidate failed the requested bounds. probe_limit_reached means the request hit probe_ceiling with ranked candidates still untested and budget remaining.

Basic

{"need":"weather"}

Require Solana

{"need":"weather","networks":["solana"]}

Discovery and the HTTP 200 selected_payment.network must be Solana from the current observed 402, never a catalog claim.

Maximum price + invocation schema

{"need":"weather","max_price_usd":0.05,"require_invocable":true}

Reject live hits above $0.05 or without an input schema.

Rank eligible candidates by merchant price

{"need":"weather","objective":"cheapest"}

Ranks the currently probed eligible candidates. It is not the cheapest listing in the catalog.

Advanced

Preview, route, and validate

GET /preview?need= is an unpaid catalog search. not_probed is always true. It returns discovery_matches and displayed (hits cap 8). Hits may include a read-only observation when history exists, or not_yet_observed.

Paid POST /route is the fail-closed live check: verify payment, discover, probe, then settle the $0.01 routing fee. POST /validate (also GET /validate?url=) is an unpaid seller probe of an already-listed URL. Fail-closed SSRF. Not a /route paywall bypass. Validate does not write observation history.

Payment flow

The $0.01 USDC is a routing fee paid to 402Signal for the check itself (10000 atomic, 6 decimals). 402Signal does not pay the selected seller and does not hold your keys. After you receive a live URL, your agent signs the seller payment and calls the seller. Copy the seller facilitator from the observed option. Do not default to x402.org.

Need, policy, and constraints

need is plain English for what to find. Optional policy compiles into structured constraints. The engine uses the structured values only. Unresolved phrases are returned in unresolved_constraints, never guessed. "Established usage" / "strong observed evidence" compile to min_observations=10. Vague "high reputation" stays unresolved. Settlement and total-cost language compile only with a numeric bound.

Structured fields include max_price_usd, max_amount_atomic, max_total_cost_usd, max_probe_latency_ms, max_service_latency_ms, max_settlement_latency_ms, require_invocable, networks, min_observations, min_observed_success, min_reputation_score, and min_reputation_confidence. max_latency_ms is a probe-RTT alias. Unknown measured values fail closed when you set the bound.

Objectives

Optional objective ranks the currently probed eligible candidates, not every discovered endpoint. Unknown values fall back to best. Same function on Base, Solana, and Algorand.

best
Default blend of need match, observed readiness, and available evidence. Missing metrics stay missing.
cheapest
Lowest known merchant price among currently probed eligible candidates. Unknown price is not treated as zero.
fastest
Lowest probe RTT on this request among currently probed eligible candidates. Not settlement latency, not historical p50. fastest_settlement is the separate settlement objective.
most_reliable
Observed success among currently probed eligible candidates when n_7d is large enough. Below 3 observations the rate is unknown, never 0. Below 10 it is weak and not a public reliability percent.
lowest_total_cost
Merchant price plus known fees. If a fee is unknown, this objective fails closed. Merchant price is not total cost.
fastest_settlement
Settlement or protocol finality, never probe RTT. Unknown finality fails closed. Do not collapse this into fastest.

search_depth=thorough or a higher max_candidates_to_probe may probe deeper. Typical requests stay at the standard plan. Hard server ceiling is 20.

prefer_network vs networks

prefer_network=base|solana|algorand is a weak ranking preference. It ranks that rail first but still searches and selects across all three. It is not a filter. networks is a hard policy lock: discovery and the HTTP 200 selected_payment.network must be in that set from the current observed 402, never a catalog claim. They are not the same knob.

selected_payment

selected_payment is the exact current observed payment option that won this route: rail, network, asset, amount, payTo, facilitator. A HTTP 200 winner is that resource plus this option. If selected_payment is missing or outside requested networks, the response is a typed miss, never 200. It is never copied from a catalog claim. Catalog rails stay on claimed payment options.

Claimed vs observed

402Signal keeps the listing and the runtime observation separate. What sellers say is available is a claim. What the endpoint returned on this check is observed. target.accepts and selected_payment use the current HTTP 402 envelope only. Claimed schemas are not observed payment options. payable requires a complete observed option. invocable is payable plus input schema. A reachable HTTP 200 is a miss, not live.

Hybrid discovery

Need-scoped search unions current upstream catalogs (Coinbase, PayAI, GoPlausible) with a process-local shadow catalog. That is not a full-world RAM index and not a published listing count. Live hits are write-through into the shadow. HTTP paths under /data stay 404.

discovery_via is a compact per-rail map (search, pages, error, or fixture). discovery_exhaustive is true only when every queried rail was untruncated and upstream_total equals returned. Paid /route also returns discovery_matches, candidates_discovered, candidates_considered, candidates_probed, discovered_count, probed_count, unprobed_count, and evaluation_complete. interpreted_constraints / applied_constraints echo constraints the engine used, including structured body keys.

Freshness clocks

Catalog rows keep three clocks: discovery (last seen in a catalog), claim (last fetched listing), and verification (last independent check). A paid route also returns this request's probe time. They are not one freshness field.

Finalist hydration

Catalog rows stay slim. Only the top 5 to 10 finalists are hydrated with claimed method, schema, and toolName (bounded, TTL). Hydration is not payment and is not an observed 402 option.

Adaptive probing

Typical plan: probe the first 3, then expand 2 to 4 more if there is no winner (standard cap 7). thorough may go to 15. Hard probe_ceiling is 20. The 55s budget can stop earlier. candidate_evaluation_complete is true only when every ranked candidate in this request's working set was probed, not the global catalog. compared is capped, but the winner always occupies a slot.

Stop reasons and miss reasons

stop_reason is why this request stopped probing: winner_selected, candidate_set_exhausted, probe_limit_reached, probe_budget_exhausted, or constraints_unmet. probe_limit_reached means the request probe_ceiling was hit with ranked candidates still untested and budget remaining. probe_budget_exhausted means ranked candidates remained when the 55s budget ended. Neither is no_candidates.

miss_reason is a closed enum: no_candidates, no_402_envelope, no_payto, reachable_200, probe_timeout, quote_expired, invalid_need, upstream_5xx, ssrf, no_input_schema, constraints_unmet, probe_budget_exhausted, probe_limit_reached, unsafe_to_probe.

Readiness

Readiness is a ladder, never a binary healthy flag: discovered, payable, invocable, recently_verified. payable=true can coexist with invocable=false. no_input_schema explains a successful payable-but-not-invocable winner. require_invocable excludes it and may return constraints_unmet. Pulse may include n_7d and rates only when n_7d >= 10. There is no public healthy and no executable_now_rate.

Reputation

Components come first: observed, usage, tenure, stability, source_count. Then a V1 reputation_score, reputation_confidence, and scoring_model_hash / scoring_model_id. A score is never returned without components. Missing is not 0. There is no public 0-100 catalog badge. Unique payer address lists are never returned. n_7d < 10 means low confidence.

Resource reputation is endpoint observations. Provider identity is not live on this API. Do not treat a catalog host as a verified provider.

Rail economics and latency

Each selected option can carry economics with provenance on every field: 402signal_observed, protocol_reference, or unknown. lowest_total_cost fails closed when a fee is unknown.

Three different latencies exist. Probe RTT is this request's check. Service p50 is historical observed latency. Settlement / finality is chain confirmation, never probe RTT. fastest uses probe RTT. fastest_settlement uses settlement or cited finality.

Validate, attestation, and pq_trust

POST /validate returns readiness, claimed vs observed, and flags. Never a binary healthy flag. Unpaid probes are GET first, then POST empty JSON only if GET was not a live 402 and POST is justified. Catalog-declared seller bodies are never POSTed. Required-body misses are unsafe_to_probe. DNS is resolved once and the TCP/TLS connection is pinned to those SSRF-checked public IPs with TLS SNI and HTTP Host set to the original hostname.

GET /attestation is a public sha256 of a recent 402signal_observed probe batch. It is a hash of that batch, not an on-chain proof.

402Signal maintains a public append-only PQ Trust log at /pq/log/checkpoint (also /pq/log/checkpoint/latest) and /pq/log/tile/*.

PQ Trust is the public name for this transparency layer. Production identity is Algorand MainNet. Falcon anchors checkpoints, not merchant payments.

The Algorand transaction authorizes a transparency-log checkpoint. It is not a merchant payment, and paid /route does not wait for blockchain confirmation.

The human-readable transparency view is available at /transparency.

Paid /route may include pq_trust.transparency with status pending, logged_uncheckpointed, or unavailable. Paid HTTP 200 (hit) and 503 (typed miss) are not atomic with log append (SEC-ROUTER-004 / A-14): those codes do not require a durable signed leaf unless the request set require_transparency. pending means a durable leaf plus a signed checkpoint. It is not a confirmed MainNet anchor. logged_uncheckpointed means the leaf is durable without a signed checkpoint and is never success when require_transparency is true. unavailable means append failed. payment_authorization.pq_native is false. There is no /trust page.
