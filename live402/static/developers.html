Use 402Signal from an agent

Find a paid API that works right now. Send the capability you need. Pay $0.01 USDC for the live routing check. Get a route with evidence, or a typed miss.

402Signal recommends the route. Your agent keeps the wallet. Every route includes evidence. Catalog claims stay separate from what the endpoint actually returns.

Send POST /route with the capability your agent needs. Use your own need string, not a canned weather example. The unpaid request returns an x402 payment challenge (HTTP 402). Sign a matching $0.01 USDC option and retry the same POST with PAYMENT-SIGNATURE (or X-PAYMENT).

Unpaid POST /route 
curl -sS -D - https://402signal.com/route -H 'Content-Type: application/json' -d '{"need":"YOUR_NEED"}'

A paid check returns HTTP 200 with a route and evidence (live, url, invocable, selected_payment, target), or HTTP 503 with a typed miss_reason. Agents that intend to pay should POST, not GET. GET with Accept: application/json (or no Accept) returns the 402 challenge so crawlers can index payment; browsers that send text/html get a human page.

MCP endpoint: https://402signal.com/mcp. Tools: route (paid live check), preview (catalog search, not probed), and validate (unpaid seller probe).

MCP server URL 
https://402signal.com/mcp

Point your MCP client at that URL. initialize, tools/list, preview, and validate need no payment. Call route with need when you want a request-time check. An unpaid route call returns HTTP 402; retry the same tools/call with a matching $0.01 USDC signature.

Preview, route, and validate

GET /preview?need= is an unpaid catalog search. not_probed is always true. It returns discovery_matches (how many listings matched) and displayed (how many rows are in hits, cap 8). If matches exceed the display cap, truncated is true. Hits may include a read-only observation when history exists, or not_yet_observed. Preview never probes and never charges.

Paid POST /route is the fail-closed live check: verify payment, discover, probe, then settle the $0.01 routing fee. POST /validate (also GET /validate?url=) is an unpaid seller probe: is this already-listed URL agent-ready? Fail-closed SSRF. Not a /route paywall bypass. Validate does not write observation history.

Payment flow

The $0.01 USDC is a routing fee paid to 402Signal for the check itself (10000 atomic, 6 decimals). 402Signal does not pay the selected seller and does not hold your keys. After you receive a live URL, your agent signs the seller payment and calls the seller. Copy the seller facilitator from the observed option. Do not default to x402.org.

Need, policy, and constraints

need is plain English for what to find. Optional policy is natural language compiled into structured constraints. The engine uses the structured values only. Unresolved phrases are returned in unresolved_constraints, never guessed. "Established usage" / "strong observed evidence" compile to min_observations=10. Vague "high reputation" stays unresolved. Settlement and total-cost language compile only with a numeric bound.

Structured fields include max_price_usd, max_amount_atomic, max_total_cost_usd, max_probe_latency_ms, max_service_latency_ms, max_settlement_latency_ms, require_invocable, networks, min_observations, min_observed_success, min_reputation_score, and min_reputation_confidence. max_latency_ms is a probe-RTT alias. Unknown measured values fail closed when you set the bound.

Objectives

Optional objective ranks live hits. Unknown values fall back to best. Same function on Base, Solana, and Algorand.

best
Default blend of need match, observed readiness, and available evidence. Missing metrics stay missing.
cheapest
Lowest known merchant price on the current observed option. Unknown price is not treated as zero.
fastest
Lowest probe RTT on this request. Not settlement, not historical p50.
most_reliable
Observed success when n_7d is large enough. Below 3 observations the rate is unknown, never 0. Below 10 it is weak and not a public reliability percent.
lowest_total_cost
Merchant price plus known fees. If a fee is unknown, this objective fails closed. Merchant price is not total cost.
fastest_settlement
Settlement or protocol finality, never probe RTT. Unknown finality fails closed. Do not collapse this into fastest.

search_depth=thorough or a higher max_candidates_to_probe may probe deeper. Typical requests stay at the standard plan. Hard server ceiling is 20.

prefer_network vs networks

prefer_network=base|solana|algorand ranks that rail first but still searches all three. networks restricts which rails are queried and selectable. They are not the same knob.

selected_payment

selected_payment is the exact current observed payment option that won this route: rail, network, asset, amount, payTo, facilitator. It is never a catalog-only rail. Catalog rails stay on claimed payment options.

Claimed vs observed

402Signal keeps the listing and the runtime observation separate. What sellers say is available is a claim. What the endpoint returned on this check is observed. target.accepts and selected_payment use the current HTTP 402 envelope only. Claimed schemas are not observed payment options. payable requires a complete observed option. invocable is payable plus input schema. A reachable HTTP 200 is a miss, not live.

Hybrid discovery

Need-scoped search unions current upstream catalogs (Coinbase, PayAI, GoPlausible) with a process-local shadow catalog. That is not a full-world RAM index and not a published listing count. Live hits are write-through into the shadow. HTTP paths under /data stay 404.

discovery_via is a compact per-rail map (search, pages, error, or fixture). discovery_exhaustive is true only when every queried rail was untruncated and upstream_total equals returned. Paid /route also returns discovery_matches, candidates_discovered, candidates_considered, and candidates_probed.

Freshness clocks

Catalog rows keep three clocks: discovery (last seen in a catalog), claim (last fetched listing), and verification (last independent check). A paid route also returns this request's probe time. They are not one freshness field.

Finalist hydration

Catalog rows stay slim. Only the top 5 to 10 finalists are hydrated with claimed method, schema, and toolName (bounded, TTL). Hydration is not payment and is not an observed 402 option.

Adaptive probing

Typical plan: probe the first 3, then expand 2 to 4 more if there is no winner (standard cap 7). thorough may go to 15. Hard probe_ceiling is 20. The 55s budget can stop earlier. candidate_evaluation_complete is true only when every ranked candidate in this request's working set was probed, not the global catalog.

Stop reasons and miss reasons

stop_reason is why this request stopped probing: winner_selected, candidate_set_exhausted, probe_limit_reached, probe_budget_exhausted, or constraints_unmet. probe_limit_reached means the request probe_ceiling was hit with ranked candidates still untested and budget remaining. probe_budget_exhausted means ranked candidates remained when the 55s budget ended. Neither is no_candidates.

miss_reason is a closed enum: no_candidates, no_402_envelope, no_payto, reachable_200, probe_timeout, quote_expired, invalid_need, upstream_5xx, ssrf, no_input_schema, constraints_unmet, probe_budget_exhausted, probe_limit_reached, unsafe_to_probe.

Readiness

Readiness is a ladder, never a binary healthy flag: discovered, payable, invocable, recently_verified. Pulse may include n_7d and rates only when n_7d >= 10. There is no public healthy and no executable_now_rate.

Reputation

Components come first: observed, usage, tenure, stability, source_count. Then a V1 reputation_score, reputation_confidence, and scoring_model_hash / scoring_model_id. A score is never returned without components. Missing is not 0. There is no public 0-100 catalog badge. Unique payer address lists are never returned. n_7d < 10 means low confidence.

Resource reputation is endpoint observations. Provider identity is not live on this API. Do not treat a catalog host as a verified provider.

Rail economics and latency

Each selected option can carry economics with provenance on every field: 402signal_observed, protocol_reference, or unknown. lowest_total_cost fails closed when a fee is unknown.

Three different latencies exist. Probe RTT is this request's check. Service p50 is historical observed latency. Settlement / finality is chain confirmation, never probe RTT. fastest uses probe RTT. fastest_settlement uses settlement or cited finality.

Validate and attestation

POST /validate returns readiness, claimed vs observed, and flags. Never a binary healthy flag. Unpaid probes are GET first, then POST empty JSON only if GET was not a live 402 and POST is justified. Catalog-declared seller bodies are never POSTed. Required-body misses are unsafe_to_probe. DNS is resolved once and the TCP/TLS connection is pinned to those SSRF-checked public IPs with TLS SNI and HTTP Host set to the original hostname.

GET /attestation is a public sha256 of a recent 402signal_observed probe batch. It is a hash of that batch, not an on-chain proof.

402Signal maintains a public append-only transparency log at /pq/log/checkpoint and /pq/log/tile/*.

Confirmed checkpoints are currently anchored to Algorand TestNet using native Falcon-1024 (f1) authorization.

The Algorand transaction authorizes a transparency-log checkpoint. It is not a merchant payment, and paid /route does not wait for blockchain confirmation.

The human-readable transparency view is available at /transparency.

Paid /route may include pq_trust.transparency with status pending or unavailable. payment_authorization.pq_native is false. There is no /trust page.

Public endpoints

These match the OpenAPI surface. Paid paths are named as code, not links, so a browser click does not hit a paywall.
